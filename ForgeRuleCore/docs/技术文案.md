# ForgeRuleCore 代码审查技术文案

> **审查对象**：`ForgeRuleCore` Swift Package（rule kernel）  
> **审查日期**：2026-07-19  
> **范围**：Core / Matchers / Geo / GeoMMDB / Config / Tests  
> **结论摘要**：内核边界清晰、核心路径可测；当前处于 **narrow compiler** 阶段，存在若干正确性与生命周期风险，不宜直接按「完整 Xray/Surge 兼容层」对外承诺。

---

## 1. 项目定位

ForgeRuleCore 是 QuantumLink / NetForge 生态中的 **L3 策略规则内核**：

```
FlowFactsResolver  →  RuleEngine.evaluate  →  RuleAction / RouteDecision
        ↑                     ↑
   FakeIP / domain      GeoSiteDB + GeoIPDB
```

| 职责内 | 职责外 |
|--------|--------|
| geosite / geoip 加载与匹配 | DNS 应答、DoH、fallback 编排 |
| 域名 / Geo 条件评估 | 包转发、socket 生命周期 |
| `RuleInput` → Direct / Proxy / Reject | NE / UI / 规则订阅下载 |

定位正确：包内保持「不可变快照 + 纯评估」，热更新与编排留给上层。

## 3. 稳定契约（审查认定）

以下行为视为当前 **事实契约**（与实现一致）：

1. `RuleEngine` 初始化后规则与 Geo DB 引用不可变；reload 需外层 snapshot swap。
2. `evaluate` 会规范化域名（小写、去首尾空白与 `.`）；空域名视为 `nil`。
3. 规则按数组顺序扫描；**首个非 `.any` 命中立即返回**。
4. `.any` 为 fallback：更新默认动作后继续扫描，允许后续具体规则覆盖。
5. 无命中时默认 `.direct`。
6. 域名类条件在 `domain == nil` 时不命中。
7. `.geoip` 使用 `resolvedIP`，不是 `originalIP`。
8. `FieldRoutingRuleFactory`：**每个 field row 最多一条 primitive 条件**（单个 domain 或单个 `geoip:`）。

### 3.1 条件支持矩阵

| 条件 | 状态 | 备注 |
|------|------|------|
| DOMAIN / `full:` | ✅ | `domainFull` |
| DOMAIN-SUFFIX / `domain:` | ✅ | `domainSuffix`；无前缀按 suffix |
| DOMAIN-KEYWORD / `keyword:` | ✅ | 线性 `contains` |
| GEOSITE | ⚠️ 子集 | `full`/`domain`/`plain`；`regex` 忽略 |
| GEOIP / `geoip:!cc` | ⚠️ 子集 | 国家码；非 CIDR 列表 |
| FINAL | ⚠️ 近似 | 用 `.any` 表达，语义非 Surge 单条垫底 |
| IP-CIDR / IP-CIDR6 | ❌ | 未实现 |
| network / port / AND / OR | ❌ | factory 拒绝或未接线 |

## 4. 代码质量审查发现

按严重级别排序。

### P0 — 正确性 / 生命周期

#### F1. MMDB 全局单例与多路径冲突（已解决）

`GeoMMDBBridge.c` 已改为每次 open 分配独立 opaque handle：

- 不同路径可并存，打开失败不会借用已有数据库。
- 每个 reader teardown 只关闭自己的 handle；不再有全局 refcount。
- 移除了误导性的 `reopen()`；reload 由上层构建并原子替换完整 snapshot。
- 真实官方 fixture 锁定了 Swift/C ABI 宏一致性、IPv4 `htonl` 边界、ownership 与 teardown。

**剩余**：snapshot provider 与 App Group bundle 版本/回滚仍属于上层集成工作。

#### F2. Config compiler 兼容投影风险（diagnostics 已落地）

`FieldRoutingRuleFactory.compile(fields:)` 已返回 accepted rules 与每个 rejected row 的稳定 reason / 原始下标，并保证 partial output 的 `isSuccessful == false`。验证使用原始数组计数，不再先过滤非法 entry 后误接受剩余项。

兼容 API `makeRule(from:)` / `makeRules(from:)` 仍只返回 accepted rules：

- 旧调用方若继续直接安装返回值，仍看不到 diagnostics。
- 新集成必须使用 `compile(fields:)` 并要求 `isSuccessful`。

**后续**：待所有集成迁移后，再考虑 deprecate / 移除兼容投影。

#### F3. `geoip:!cc` 在 lookup 失败时恒为 true

```swift
return !matchPositive(key: inner, ip: ip)
// matchPositive 在 lookup 返回 nil 时为 false
// 因此 !false == true
```

未知国家 / 私网 / MMDB miss 的 IP 会命中所有 `geoip:!cn` 类规则。  
这可能是期望行为（「非 CN 走代理」），但必须在契约中写死，并补测试；否则集成方会按「明确非 cn」理解而踩坑。

---

### P1 — API / 语义一致性

#### F4. Public API 面过宽

几乎所有 matcher、JSON model、`MMDBReader`、`GeoIPProvider` 均为 `public`。  
稳定内核实际只需要：

- `Rule` / `RuleInput` / `RuleAction` / `RuleEngine` / `RuleCore`
- `FlowRuleClassifier` / `FlowFactsResolving` / `FakeIPStore`
- Config DTO + Factory
- `CountryLookup`（注入点）
- Bundle 装配入口

**风险**：内部结构（trie 节点布局、MMDB bridge）成为外部依赖后，重构成本高。  
**建议**：下一版本标注「stable vs internal」，或逐步改为 `package` / 非 public。

#### F5. `.any` 与 Surge `FINAL` 语义不一致

当前 `.any` 可放在列表前部作为「可被覆盖的默认动作」。  
Surge `FINAL` 习惯是「最后一条，之后不再匹配」。  
两者都能表达默认路由，但配置迁移时容易写错。

**建议**：文档固定推荐写法（`.any` 放末尾，且其后不再放规则），或新增显式 `final` 条件并在引擎中短路。

#### F6. GeoSite `regex` 与 attributes 被忽略

- `regex` 类型 DEBUG 打印后 `continue`。
- `attributes` 解码但不使用。

若官方 geosite 依赖 regex / `@cn` 等 attribute，行为会与上游数据静默不一致。

### P1 — 实现细节

#### F7. `DomainSuffixTrie` 查询路径额外分配

`containsSuffix` 对每个 label 执行 `String(labelSub)`。  
GeoSite 热路径上，标签数虽小，但在 Extension 高频 classify 中仍可优化为 `Substring` 字典键或 UTF8 视图。

另：局部变量名 `tire` 疑似 `trie` 笔误，不影响正确性，影响可读性。

#### F8. `DomainKeywordMatcher` 线性扫描

复杂度 \(O(K \cdot |d|)\)。当前 geosite keyword 规模下可接受；若未来合并大量 plain 规则，应考虑 Aho-Corasick。

#### F9. `GeoIPDB` 缓存键与双重 Optional

`parsedKeyCache: [String: CountryCode?]` + `if let cached = parsedKeyCache[norm]` 依赖 Swift 对「字典值本身是 Optional」的解包语义，可读性差，易在后续改动中引入「缓存 miss / 命中 nil」混淆。

Preheat 用 `if cache[positive] == nil` 无法区分「未插入」与「插入了失败解析」；功能上大多无害，但应改成显式 `contains` 或非 Optional 值 + tombstone。

#### F10. `RuleEngine` 与 Resolver 重复 normalize

`FlowFactsResolver` 与 `RuleEngine.evaluate` 都会 `normalizeDomain`。  
防御性重复可接受，但应在契约中声明「evaluate 始终自规范化」，避免调用方以为必须先 resolve。

#### F11. `RuleInput.port` / `proto` 未被引擎消费

字段已进入输入模型，但 `matches` 完全忽略。  
与 config 侧 `parseNetworkList`「解析后拒绝」一致地表明：**组合条件尚未接线**。  
建议在类型或文档上标记 `reserved`，避免集成方误以为已支持端口分流。

---

### P2 — 测试与工程

#### F12. 测试覆盖仍缺生产规模与并发集成

现有 56 个 `@Test`，对 narrow contract 与 bundle I/O 覆盖良好：

- FlowFactsResolver
- FieldRoutingFactory / JSON decode
- Matchers / GeoIP stub / GeoSite temp JSON
- RuleEngine 顺序与 fallback

缺口：

- 更大的生产 `geoip.mmdb` / 边界 fixture（小型官方 reader fixture 已覆盖）
- 官方 geosite / routing 样例兼容
- 并发 classify + reload
- bundle 版本 manifest、checksum 与 rollback

#### F13. Bundle 装配硬编码文件名

`Rules/geosite.json` / `Rules/geoip.mmdb` 是与 QuantumLink 0.8.0 一致的 App Group 固定 layout；loader 会区分 container 无效、文件缺失、geosite 损坏与 MMDB 打开失败，并通过可注入 resolver 做真实 I/O contract test。
剩余风险是无版本 manifest、checksum 与 rollback 元数据；这些应与 snapshot provider 一起设计。

## 5. 复杂度速查（评估热点）

| 组件 | 时间 | 空间 |
|------|------|------|
| `RuleEngine.evaluate` | \(O(R \cdot C)\) | \(O(1)\) 额外 |
| `DomainSuffixTrie` 查询 | \(O(L)\) 标签数 | 与数据线性 |
| `DomainExactSet` | \(O(|d|)\) 均摊 | \(O(n)\) |
| `DomainKeywordMatcher` | \(O(K \cdot |d|)\) | \(O(K)\) |
| `GeoSiteDB.contains` | dict \(O(1)\) + 上三者 | 全量索引 |
| `GeoIPDB.match` | 解析 + MMDB lookup | preheat 缓存 |

当前热点更可能在每个 reader 的 **MMDB 串行队列**，而非域名 trie。在补 CIDR / 组合条件前，不建议过早做规则索引。
